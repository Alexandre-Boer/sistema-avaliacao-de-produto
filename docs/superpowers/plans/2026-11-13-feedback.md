# Feedback (Avaliações de produto) — Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Página de detalhes `/products/<id>` mostrando o produto, todas as avaliações existentes e, para pessoas logadas, um formulário de nova avaliação (nota 1–5 + comentário); pessoas deslogadas veem um bloco pedindo autenticação. Endpoint `POST /api/v1/products/<id>/feedbacks` persiste em `products_feedbacks`.

**Architecture:** A tabela `products_feedbacks`, o tipo `Product` e o módulo de sessão (`getSession`) já existem (Fase 0). A página é um Server Component que busca produto, avaliações e sessão em paralelo e decide entre `FeedbackForm` (client) e `AuthRequired`. Com `cacheComponents` ativo, um `loading.tsx` cria o boundary de Suspense da rota. O formulário envia via `useMutation` e, no `201`, chama `router.refresh()` para a lista server-rendered incluir a nova avaliação. O endpoint exige sessão (`401`), valida com zod (`400`) e responde `404` quando o produto não existe.

**Tech Stack:** Next.js 16 (App Router, `cacheComponents`), React 19, react-hook-form + zod, TanStack Query, nanoid, shadcn/ui (`card`, `textarea`, `alert`, `button`, `skeleton`, `badge` já instalados), Vitest + Testing Library.

**Spec:** `specs/feedback.md` (ver também `docs/superpowers/plans/2026-11-13-orquestracao.md` para contratos e donos de arquivos)

## Global Constraints

- Tabela `products_feedbacks` com `id` (nanoid), `score` (int 1–5), `comment`, `created_at`, `created_by` (= `Session.accountId`), `product_id`.
- Deslogado: bloco exigindo autenticação (link para `/auth/sign-in`), sem formulário. Logado: formulário com nota 1–5 + comentário.
- A página lista **todas** as avaliações do produto e **depois** renderiza o formulário.
- `created_by` vem **somente** da sessão (`getSession()`), nunca do body.
- Não editar arquivos de outros donos (ver orquestração): `src/lib/session.ts`, `src/server/products/product.ts`, `src/components/layout/**`, `src/app/(site)/page.tsx`, migrations, `package.json`.
- Lint/format com Biome; TypeScript estrito; Server Components que acessam banco/cookies ficam sob Suspense (`loading.tsx`).

## Review Focus

1. **Body com `created_by` ou `productId` forjados** deve ser ignorado: o serviço recebe `accountId` da sessão e `productId` da URL. Teste: Task 3 (passo 1, "ignora created_by do body").
2. **Produto inexistente** (`/products/nao-existe` e `POST` para id inválido) → página `404` e endpoint `404`, nunca `500`. Testes: Task 2 (passo 1, `getProductById` → `null`; `createFeedback` FK `23503` → `ProductNotFoundError`) e Task 3 (passo 1, caso 404).
3. **Nota fora de 1–5 ou não inteira** (`0`, `6`, `4.5`, `"5"` como string) — o schema aceita `"5"` por `coerce` mas rejeita o resto. Teste: Task 1 (passo 1, casos de nota).
4. **Sessão expirada entre carregar a página e enviar**: o formulário recebe `401` e mostra mensagem com link para entrar, não um erro genérico. Teste: Task 4 (passo 1, caso 401).
5. **Comentário só com espaços** deve ser rejeitado nas duas camadas (schema compartilhado com trim). Teste: Task 1 (passo 1, "rejeita comentário em branco").
